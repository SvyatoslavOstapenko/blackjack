# БлэкДжек

Веб-приложение для игры в блэкджек с ведением истории раздач и учётом баланса игроков.
Учебный проект по дисциплине «Автоматизация процессов жизненного цикла программных средств»,
Московский политехнический университет.

## Назначение

Система позволяет зарегистрированному игроку делать ставки виртуальными фишками, играть
раздачи в блэкджек против дилера по стандартным правилам, просматривать историю своих
раздач и общую таблицу лидеров. Администратор начисляет фишки, сбрасывает баланс
и удаляет ошибочные раздачи.

**Система оперирует только виртуальными фишками. Реальные деньги, платёжные средства
и вывод средств не поддерживаются.**

## Уточнение технического задания

Тема придумана самостоятельно, в списке вариантов преподавателя её нет — общая часть
списка это прямо разрешает («приветствуется уточнение и расширение задания для приведения
его к более "настоящему" виду»). Уточнения и ограничения, принятые относительно
«просто блэкджека»:

- игра один на один с дилером; из действий только «Ещё» (hit) и «Хватит» (stand),
  без сплита, страховки и удвоения;
- дилер добирает карты, пока очков меньше 17, и останавливается на 17 и выше;
- блэкджек (21 с двух карт) оплачивается 3:2, обычная победа — 1:1, ничья — возврат ставки;
- ставка только чётная: при выплате 3:2 нечётная ставка дала бы дробное число фишек,
  а баланс — целое;
- стартовый баланс нового игрока — 1000 фишек, уйти в минус нельзя
  (ограничение `balance >= 0` на уровне БД);
- колода в базе не хранится: оставшиеся карты вычисляются как 52 минус уже выданные
  в текущей раздаче;
- фишки виртуальные, реальных денег и платежей в системе нет.

## Функциональность

| Код | Функция | Эндпойнт |
|---|---|---|
| Ф1 | Регистрация игрока, стартовый баланс 1000 фишек | `POST /register` |
| Ф2 | Вход в систему по никнейму и паролю | `POST /login` |
| Ф3 | Начало раздачи с указанием ставки, проверка достаточности баланса | `POST /rounds` |
| Ф4 | Действие «Ещё» — добор карты с проверкой перебора | `POST /rounds/{id}/hit` |
| Ф5 | Действие «Хватит» — ход дилера и завершение раздачи | `POST /rounds/{id}/stand` |
| Ф6 | Расчёт результата и выплаты, обновление баланса | внутри Ф4/Ф5 |
| Ф7 | Просмотр истории раздач — карты обеих рук, счёт, ставка, выплата | `GET /rounds` |
| Ф8 | Просмотр таблицы лидеров, сортировка по убыванию баланса | `GET /leaderboard` |
| Ф9 | Администрирование баланса и раздач: начисление фишек, сброс баланса, удаление раздачи | `POST /admin/…` |
| Ф10 | Обработка пользовательских исключительных ситуаций | хуки-обработчики FastAPI |
| Ф11 | Контроль работоспособности — доступность приложения и соединение с БД | `GET /health` |

## Схема базы данных

| Таблица | Назначение | Основные поля |
|---|---|---|
| `players` | игроки, их баланс и права | `id`, `nickname`, `password_hash`, `balance`, `rounds_played`, `is_admin` |
| `rounds` | раздача: ставка, статус, выплата | `id`, `player_id`, `bet`, `status`, `payout`, `started_at`, `finished_at` |
| `hands` | рука игрока и рука дилера в раздаче | `id`, `round_id`, `owner`, `score` |
| `cards` | карты руки в порядке выдачи | `id`, `hand_id`, `rank`, `suit`, `order_no` |

## Сборка и развёртывание (план ЛБ3)

Контейнерное развёртывание будет реализовано в ЛБ3. Для него потребуется Docker и docker compose.

1. Склонировать репозиторий:

    git clone https://github.com/SvyatoslavOstapenko/blackjack.git
    cd blackjack

2. Создать файл `.env` на основе `.env.example` и заполнить значения:

    cp .env.example .env

3. Запустить:

    docker compose up -d

4. Проверить: http://localhost:8000/health — должно вернуться `{"status": "ok"}`

Подробная инструкция появится после выполнения ЛБ3.

## Прототип ЛБ2

В текущем каркасе реализована только проверка работоспособности `/health`.
Игровые функции и модели базы данных будут реализованы в ЛБ3.

Для запуска прототипа на Ubuntu:

    python3 -m venv .venv
    . .venv/bin/activate
    pip install -r requirements.txt
    uvicorn app.main:app --host 0.0.0.0 --port 8000

Проверка: `curl http://localhost:8000/health`.
