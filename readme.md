# БлэкДжек

Веб-приложение для игры против дилера с учётом виртуальных фишек и историей раздач. Реальные деньги, платежи и вывод средств не поддерживаются.

## Возможности

- Гостю доступны вход, регистрация, правила и таблица лидеров.
- Новый игрок получает 1000 фишек. Пароли хранятся в виде Argon2-хешей.
- Авторизованный игрок начинает раздачу, выбирает «Ещё» или «Хватит», видит баланс и историю с картами обеих рук.
- Незавершённая раздача сохраняется в БД и восстанавливается после перезапуска приложения или обновления страницы.
- Администратор просматривает игроков, начисляет фишки, возвращает баланс к 1000 и удаляет ошибочные завершённые раздачи.
- При удалении раздачи отменяются её ставка и выплата и уменьшается счётчик раздач. Операция отклоняется, если результат сделал бы баланс отрицательным. Активную раздачу удалять нельзя; сброс баланса при активной раздаче запрещён.
- Начисление фишек и отмена старой раздачи учитывают возможную выплату по активной руке, чтобы не переполнить баланс.

## Локальный запуск на Windows

Нужен Python 3.12. В PowerShell, из папки проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m app.local --port 8006
```

Открыть http://127.0.0.1:8006 и зарегистрироваться. Для повторного запуска достаточно последней команды либо файла `Запустить.ps1`.

Этот режим использует отдельную локальную SQLite-базу `data/local/blackjack.sqlite3`. Ключ сеанса создаётся случайно и сохраняется в `data/local/auth.key`; каталог `data` исключён из Git и Docker-контекста. Не удаляйте его для сохранения локальных аккаунтов и раздач. Сервер слушает только 127.0.0.1. Закрытие консоли останавливает сервер.

Создать отдельную учётную запись администратора:

```powershell
.\.venv\Scripts\python.exe -m app.local --create-admin НИКНЕЙМ
```

Пароль вводится локально без отображения. Существующая учётная запись не перезаписывается; регистрация через сайт всегда создаёт обычного игрока. Для другого `--data-dir` при создании администратора укажите тот же путь, что использовался при запуске сервера.

Время истории показывается по Москве (МСК). Сеанс действует до 8 часов. «Выйти» удаляет токен из вкладки браузера; уже скопированный токен остаётся действительным до истечения срока. Для локального учебного использования не предусмотрено центральное отзывание токенов.

## PostgreSQL и Docker Compose

Основной стек: Python 3.12, FastAPI, SQLAlchemy, PostgreSQL 16. Локальный SQLite-режим нужен для отдельной проверки приложения и не заменяет проверку PostgreSQL на стендах.

Скопируйте `.env.example` в `.env` и заполните `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `AUTH_SECRET`. Для ключа используйте случайное значение не менее 32 символов. Не публикуйте `.env` и файлы ключей.

```bash
docker compose up -d --build
curl http://127.0.0.1:8000/health
```

Инициализация `python -m app.init_db` создаёт отсутствующие таблицы, но не выполняет миграции существующей схемы. Данные PostgreSQL находятся в томе `pgdata`. Рабочие изменения схемы применяются отдельно. Не используйте `down -v`, если нужно сохранить данные.

Для создания администратора в уже запущенном Compose-проекте:

```bash
docker compose exec app python -m app.create_admin НИКНЕЙМ
```

## Основные API

| Назначение | Маршрут |
|---|---|
| Веб-интерфейс | GET / |
| Регистрация и вход | POST /register, POST /login |
| Профиль | GET /me |
| Начало, добор, завершение | POST /game/start, /game/hit, /game/stand |
| Активная раздача | GET /game/active |
| Личная история, детали | GET /game/rounds, /game/round/{id} |
| Лидеры, до 10 игроков | GET /leaderboard?limit=10 |
| Игроки для администратора | GET /admin/players |
| Начисление, сброс | POST /admin/players/{id}/credit, /admin/players/{id}/reset |
| Завершённые раздачи игрока | GET /admin/players/{id}/rounds |
| Удаление ошибочной раздачи | DELETE /admin/rounds/{id} |
| Приложение и соединение с БД | GET /health |

Защищённые API получают заголовок `Authorization: Bearer <токен>`. Веб-интерфейс добавляет его автоматически. Токен хранится в sessionStorage вкладки, пароли в браузере приложение не сохраняет. История и списки администратора поддерживают `limit` и `offset`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Проверки создают временные SQLite-базы. Они не используют `.env`, рабочую БД или стенды. Проверяются правила, выплаты, авторизация, изоляция игроков, конкурирующие запросы, администрирование, ошибки БД и статические ресурсы страницы. Успех локальных проверок не доказывает выполнение CI/CD, миграций или резервного копирования.

При установленном Node.js можно отдельно проверить обработку запоздавших ответов, выхода из аккаунта и таймаутов интерфейса:

```powershell
node --test tests/frontend.test.cjs
```

Веб-интерфейс не повторяет изменяющий запрос автоматически при сетевой ошибке. После таймаута обновите страницу, чтобы проверить сохранённый результат. Ответы, пришедшие после выхода из аккаунта, не восстанавливают прежний сеанс на экране.
